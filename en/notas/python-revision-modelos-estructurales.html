Useful software preserves the meaning of results. The storey-results demonstrator shows how to validate units, compare compatible states and document transformations before drawing conclusions.

The structural question defines the program

Model review starts by identifying a decision that requires evidence: locating a stiffness change, comparing service displacements or checking equilibrium. Variables, response states and tolerances follow from that decision. Python makes operations repeatable and exceptions traceable; interpreting a difference still requires understanding the structure, loading and idealization.

The laboratory supports this method with executable code, synthetic data and tests that let a reviewer follow each transformation from the original CSV to the tables and plots.

Define a contract before reading the CSV

The csv module turns rows into records but has no knowledge of units or structural compatibility [1]. The demonstrator requires case, level, elevation, displacement, elevation_unit and displacement_unit. Each case represents one signed, simultaneous displacement state at the same levels.

Before processing commercial exports, review selected cases, axes, measurement locations and the meaning of each result [2–3]. Real exports must be mapped to the documented format while preserving provenance. No automatic connection to ETABS or SAP2000 is implemented here.

Normalize without hiding errors

Input accepts m, cm and mm. Processing normalizes both elevations and displacements to metres. Displays may express displacement in millimetres with the unit clearly identified. Unknown units are rejected, along with missing fields, duplicate records, nonfinite values and incompatible level profiles. Silently replacing an empty cell with zero would change the model being reviewed.

Case and level names follow the documented contract, excluding identifiers that spreadsheet software might interpret as formulas. Preserve the original file separately from processed results and identify the reference case, output units and code version.

A checkable example: two service profiles

SERVICE_A contains elevations of 0, 3, 6 and 9 m and displacements of 0, 2, 6 and 12 mm. SERVICE_B uses the same elevations with displacements of 0, 3, 8 and 15 mm. Differences B − A are 0, 1, 2 and 3 mm. For A, geometric drift ratios are 0.000667, 0.001333 and 0.002. The maximum for B is 7/3000 ≈ 0.002333.

These values are calculated between consecutive levels in the same response state. They are not amplified code-defined drift demands and are not automatically compared with a limit. Modal envelopes or independent time-history maxima require different processing and are invalid inputs for this subtraction.

Δuᵢ = uᵢ,B − uᵢ,A; θᵢ = (uᵢ − uᵢ₋₁)/(1000 × (zᵢ − zᵢ₋₁)), with u in mm and z in m
from math import isclose

z_m = [0.0, 3.0, 6.0, 9.0]
u_mm = [0.0, 2.0, 6.0, 12.0]
drift = [(u_mm[i] - u_mm[i-1]) / (1000 * (z_m[i] - z_m[i-1]))
         for i in range(1, len(z_m))]
assert isclose(max(drift), 0.002, rel_tol=1e-12)

Test results and rejected inputs

An independent check verifies the maximum above; other inputs should produce controlled errors. Converting all input displacements from mm to m should preserve the result, while shuffling rows should not change the sorted profile. Numerical comparisons require explicit tolerances and finiteness checks [4]. unittest organizes these checks [5].

The second demonstrator offers a different benchmark: an elastic cantilever with a closed-form solution. It helps distinguish data parsing, equilibrium, parameter dependence and mechanical scope. None of these checks establishes code compliance on its own.

From results to the technical report

Automation supports traceability when another engineer can reconstruct the operation and understand its limits. A plot should lead to a specific structural question and a documented decision.

  • Record the files and cases compared, including units and assumptions.
  • Separate rejected data, geometric findings and outstanding code checks.
  • Preserve original exports, processed CSV/JSON results and the code revision.
  • Manually review representative cases and explain discrepancies.
